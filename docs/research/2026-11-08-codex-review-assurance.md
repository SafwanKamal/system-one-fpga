# Review of the industrial command gate

November 8, 2026. This review combines the assurance agent's source findings with the coordinating reviewer's independent Python probes. It evaluates the current `gate_core`, bridge, frame model and proposed H1–H4 claims. Source hashes and probe outputs are in [review checks](2026-11-08-codex-review-checks.json). The concrete probe results concern the Python reference. The corresponding RTL behavior was inspected in source. Endpoint consequences are stated under TCP and PLC assumptions and still require an independent stack or controller test.

The strongest issue is that forwarding an Ethernet frame does not establish that the PLC accepted its command. The observer currently makes that substitution. A small rule circuit can agree perfectly with its reference while the two share that incorrect assumption. [Frame model](../../src/sysone/v2/agent_gate/frames.py:175) · [RTL state update](../../rtl/v2/gate/gate_core.sv:296)

## Concrete counterexamples and missing state

| Finding | Observation | Consequence |
|---|---|---|
| TCP checksum is ignored | In a fresh `GateModel`, send an FC6 outlet=100 frame with valid Ethernet FCS and deliberately invalid TCP checksum. It forwards and stores outlet=100. A later TCP-checksum-valid pump=100 frame also forwards. Both return rule PASS. The checksum residuals in the probe are 65279 and 0 respectively. | A conforming established TCP receiver rejects the first segment. If the next valid segment is at its expected sequence, it can accept pump=100 while the valve remains closed. This is a candidate monitor/endpoint discrepancy, independently reproducible without changing any gate policy. TCP requires receiver checksum verification. [RFC 9293 §3.1](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.1) |
| Read correlation ignores Unit ID | A request for unit 1 and a response for unit 2 with the same transaction ID updates the global level from 500 to 900 in tenths of a percent. | A valid response concerning another device can alter admission for this device. The table also omits the TCP connection identity and request age. [Model table and update](../../src/sysone/v2/agent_gate/frames.py:156) · [RTL matching](../../rtl/v2/gate/gate_core.sv:285) |
| Writes update before acceptance | State changes at the gate's forward verdict, before bridge transmission and without inspecting a successful write response. | PLC exceptions, duplicate or out-of-window TCP bytes, failed transmission, PLC-side clamps and local controller changes can diverge from the recorded actuator setpoints. A successful Modbus response establishes a narrower fact than physical actuator motion. |
| No initial knowledge or freshness state | Reset sets level to 50% and every actuator to zero. The observer stores no measurement timestamp or uncertainty interval. | It can admit commands before learning the plant state, or continue using a once-valid sample after the plant changes. Correct deployment needs explicit initialization, freshness and local-control assumptions. [Reset](../../rtl/v2/gate/gate_core.sv:146) |
| Denial drops TCP bytes | An unsafe ADU is suppressed as an Ethernet frame while the connection otherwise passes through. | The receiver's byte stream has a gap. Later operations on that connection may wait behind the repeatedly rejected bytes. Recovery through reset/reconnect or a terminating proxy must be specified and measured. [TCP sequence model](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.3) |

The current test generator always gives frames the same TCP sequence and acknowledgment values. It inserts a fresh poll before each replayed write. These are useful parser vectors, but they do not exercise an endpoint's real byte-stream acceptance. Agreement between the frame reference and RTL on those vectors establishes implementation agreement for that traffic. It does not transport the original oracle-state policy catch rates to a real network. [Frame generation](../../src/sysone/v2/agent_gate/frames.py:45) · [Synthetic poll insertion](../../src/sysone/v2/agent_gate/frames.py:203)

Segmentation and coalescing also need a defined policy. A single Modbus ADU can span TCP segments, and one segment can contain several ADUs. Rejecting those cases can be a deliberately restricted deployment profile. General transparent Modbus compatibility would need consistent stream reconstruction, overlap handling and endpoint semantics. Merely adding checksum validation leaves these issues and acknowledgment uncertainty unresolved.

The checksum example assumes a raw sender on the untrusted agent side and a trusted, conforming PLC TCP stack. It does not require compromising the plant side. The unit-correlation probe demonstrates insufficient matching logic. Whether a given deployment exposes multiple unit IDs or flows is a separate profile condition. If the plant itself can forge arbitrary observations, a passive observer has a more fundamental trust problem. Two physical states may be consistent with the same transcript and require different actions. A useful guarantee needs a trusted measurement source or a conservative set of possible states under a declared model.

## What the current hardware evidence supports

The ideal-stream core's 57,562 rule vectors and 26,961 frame checks provide useful implementation evidence. The OOC result reports 3,456 LUTs, or 2.95% of K26 LUT capacity, and an 11-cycle decision after the last frame byte. The prose claim of less than 1% conflicts with that table. The OOC core excludes PHY handling, frame buffers, clock crossings, secure configuration and the approval path. [Step-1 report](2026-11-08-agent-gate-hardware-step1.md)

The new bridge has a shared gate input of one byte per 125 MHz cycle. Before accounting for parser gaps, that is an aggregate 1 Gb/s inspection capacity. Two simultaneously saturated receive ports offer 2 Gb/s. Its per-direction state machine loads a complete frame, waits for a decision, transmits, then allows another frame to load. For large forwarded frames, even the optimistic load-plus-transmit schedule approaches half a gigabit per second per direction. The queue can absorb bursts, but finite storage cannot maintain lossless service indefinitely above its service rate. These are source-derived limits, pending simulation or target measurement. [Bridge state machine](../../rtl/v2/gate/bridge/gate_bridge_core.sv:131)

The latency counter begins when a frame descriptor is popped, after reception and any queue residence. It therefore cannot establish the proposed ingress-to-egress delay under flood. At 1 Gb/s, receiving 1,518 bytes alone takes 12.144 microseconds, before preamble and the additional store-and-forward work. A ten-microsecond target needs explicit packet sizes, admission rate, direction mix, queue contract and timestamp boundary. Separate delay for accepted traffic from congestion drops and command starvation. Empirical p99.99 and maximum observations do not prove a worst-case bound. [Counter origin](../../rtl/v2/gate/bridge/gate_bridge_core.sv:133) · [Counter update](../../rtl/v2/gate/bridge/gate_bridge_core.sv:239)

H1 has two different attacker scopes. Separating the planner onto another physical host can protect the gate from that host's root privileges if the topology has no bypass. Resisting root on the KR260 A53 additionally requires protected configuration, bitstream loading, reset/clock/PHY control, memory/state paths and approval keys. RC1 currently relies on privileged Linux for overlay loading. That operating arrangement is useful for research deployment but supplies no evidence of H1 for an adversarial A53 root. Authenticated boot must be paired with continued control of reconfiguration and trusted administration. [RC1 operating model](../../hardware/BASELINE.md)

H3 should inventory required trusted components and interfaces. RTL line count divided by the entire Linux kernel is a source-size comparison, not a measured reduction in exploitable attack surface. A small external MCU or software appliance can have the same separation from the agent host. Compare equal authority, policies, observation semantics and deployment function. Include PHY/MAC logic, TCP processing, parser, policy configuration, firmware and the boot/configuration root in the relevant TCB.

H4 exact replay is valuable for debugging a deterministic policy. To replay the actual release decision, record the correlated observations, clock/age, policy version, connection epoch, command identity, reset/overflow events and any approval consumption. A checksum or hash of an incomplete decision log cannot reconstruct missing state. If logs must resist compromised software, protect the capture and binding path as well as storage.

## More defensible next experiment

Start with an independent TCP/Modbus server and explicit modeled actuator registers. Replay valid and invalid checksum traffic, splits, coalesced ADUs, overlap and retransmission, wrong Unit ID, concurrent connections, exceptions, delayed responses, dropped confirmations and reconnects. The oracle should be the command stream the independent endpoint accepted. Track physical simulation separately. Include the current optimistic observer as a deliberately weak control.

Choose a bounded transport contract. A transparent profile could restrict flow counts and supported frame forms, terminate an unusable flow, mark its effect state unknown and require reconciliation before resuming. Its availability cost must be measured. A Modbus-terminating proxy can send an explicit operation-level exception while keeping a client connection usable, with a larger TCP implementation and different deployment semantics. Choose based on the intended requirement and compare the alternatives in the experiment.

Require the observer's state estimate to contain every PLC state possible under its stated loss, acceptance, local-control and observation assumptions. Admit a command only when the declared policy permits it in all remaining states. Acknowledgments and correlated readbacks can narrow that set. For continuous process quantities, include elapsed time, bounded sensor error and model drift. If no useful estimate remains, explicitly request new evidence, hold with a bounded budget, or use the declared recovery controller.

The gate's release edge must recheck command identity, policy generation, relevant observation validity and single-use approval. A hash of frame bytes plus a deadline alone omits state changes and replay. A Modbus success response still does not certify physical motion, so the theorem must name register-state or physical-state assumptions.

Compare the same observer and policy in optimized C on an external trusted host, a bounded MCU profile if feasible, and the PL/R5 design. Keep transport handling and authority equivalent. The useful FPGA result would be a proven and measured bound at the release interface under explicit traffic admission, with recovery and useful command delivery retained. If software already meets that envelope at lower cost, the research result may concern the observer and its test method instead of the hardware.

This review identifies concrete correctness work and research hypotheses. It establishes no first-of-kind claim for a general AI firewall, partial-observation shield or replay log.

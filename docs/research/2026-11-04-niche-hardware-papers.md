# Hardware, accelerator runtime, and measurement literature

Screened November 4, 2026. This companion covers 40 research papers. It prioritizes DDR-backed embedded FPGA decoders, then examines rollback and isolation, comparable edge systems, energy methods, and the encoder lineage. I screened primary abstracts and selected full-text passages for H01, H02, H04, H05, H14, H39 and H40. Years use publication year when established and otherwise the preprint year or dated version indicated. Measurements below are authors' reported results in their respective experimental setups. Preprints are marked where they affect interpretation.

## Embedded FPGA systems closest to v9d and v9e

| ID | Paper | Finding and relevance |
|---|---|---|
| H01 | Hummingbird (2025, ICCAD) | On the closely related KV260, the accelerator runs LLaMA3-8B at 4.8 decode tokens/s. Column-aligned transfers, a DSP reduction path and GQA dataflow address DDR utilization. Its much larger, lower-bit model and reporting boundary rule out a direct speed comparison to Qwen3-0.6B Q8_0. [Paper](https://arxiv.org/html/2507.03308v1) |
| H02 | Pushing up to the Limit of Memory Bandwidth and Capacity Utilization for Efficient LLM Decoding on Embedded FPGA (2025, DATE) | Bare-metal KV260 fits LLaMA2-7B in 4 GB and reports roughly five decode tokens/s with 93.3% memory capacity utilization. Its fused dataflow and layout are credible DDR baselines. System One's Linux residency and lease semantics address a different problem from maximizing bare-metal capacity. [Paper](https://arxiv.org/abs/2502.10659) |
| H03 | LlamaF (2024 preprint) | Asynchronous pipelined matvec and post-training quantization accelerate TinyLlama-1.1B by 14.3–15.8× against its own ZCU102 processing-system baseline. The paired same-board control is a useful template for measuring v9d against resident Cortex-A53 inference. [Paper](https://arxiv.org/html/2409.11424v1) |
| H04 | TeLLMe v2 (2025 preprint) | Implements end-to-end prefill and decode with ternary weights and INT8 activations using table lookup, fused elementwise operations and a reversed prefill-attention schedule. Reports up to 25 decode tokens/s and 0.45–0.96 s TTFT for 64–128 tokens. Compare workload and precision separately. The result establishes prior end-to-end prefill optimization on edge FPGAs. [Paper](https://arxiv.org/html/2510.15926v1) |
| H05 | PD-Swap (2025 preprint) | Reconfigures just the attention region between phases while preserving the ternary matrix and weight-buffer datapaths. Reports up to 27 decode tokens/s. Its runtime logic-swap protocol is pertinent if System One ever changes bitstreams per phase. The current v9d/v9e comparison uses separate packages and runs. [Paper](https://arxiv.org/html/2512.11550v1) |
| H06 | DeltaLLM (October 2026 v2 preprint) | Near-diagonal exact attention and approximate nonlocal delta-key reuse expose sparsity to a specialized prefill engine. The KV260 implementation reports 1.62× prefill speedup against TeLLMe v2. This is a recent same-board challenge to a generic attention-speed novelty claim. Its average quality evidence answers a different question from exact parity for every retained state. [Paper](https://arxiv.org/abs/2507.19608v2) |
| H07 | TerEffic (2025 preprint) | Provides distinct all-on-chip and HBM configurations for ternary inference. Its headline 16,300 tokens/s refers to a 370M model with weights on chip. The relevant idea is specializing for a low-bit representation. That operating point gives no projected KR260 DDR throughput. [Paper](https://arxiv.org/abs/2502.16473) |
| H08 | EdgeLLM (2025 journal) | Uses grouped systolic mixed-precision units and a compiler that shares layouts across attention and FFN operators. Despite the name, the tested VCU128 uses HBM. It is a comparison for the dataflow and operator fusion in v9d, with a different memory and power envelope. [Paper](https://arxiv.org/abs/2407.21325) |
| H09 | FlightLLM (2024) | Configurable sparse DSP chains and an always-on-chip decode schedule target FPGA-specific locality. LLaMA2-7B batch-one comparisons use the Alveo U280 and a specific GPU baseline. Sparse compute and locality are established lines of work, and System One's Q8_0 DDR path is a separate operating point. [Paper](https://arxiv.org/abs/2401.03868) |
| H10 | DFX (2022, MICRO) | Runs GPT-2 end to end on four U280s with model parallelism and custom instructions for prompt processing and generation. Phase-specific FPGA dataflow has clear precedent. An appliance-level speedup cannot isolate the contribution of two-query prefill on one K26. [Paper](https://arxiv.org/abs/2209.10797) |
| H11 | LUT-LLM (2025 preprint) | Co-quantizes activation and weight vectors for centroid lookup and uses hybrid spatial/temporal organization. Its customized Qwen3-1.7B deployment on an AMD V80 suggests a future model–hardware co-design experiment that would need a new quality qualification. [Paper](https://arxiv.org/abs/2511.06174) |
| H12 | LoopLynx (2025 preprint) | Reuses large spatial dataflow kernels over time and overlaps distributed transfers across FPGAs. Its two-board GPT-2 study separates benefits of kernel organization and device scaling. K26 faces the former problem within one device. [Paper](https://arxiv.org/abs/2504.09561) |
| H13 | FAST-Prefill (2026 preprint) | Uses a liveness-guided two-tier cache for dynamic sparse attention on U280, with evaluations at 4K–128K tokens. It establishes prefill data movement as an optimization target. System One's 1K–2K context and exact replay call for different controls. [Paper](https://arxiv.org/abs/2602.20515) |

## Cache reuse, rollback, and isolation

| ID | Paper | Finding and relevance |
|---|---|---|
| H14 | Aborted but Not Forgotten (2026 preprint) | Token-matched audits show retained KV changes protected effects after an apparent abort in 25 of 63 dense-model test cells. Transaction-local restore closes the studied channel, including reproductions using framework session paths. The existing result covers the logical restore idea. A KR260 contribution would have to establish the physical completion and write-isolation conditions that make it valid on a shared scratch bank. [Paper](https://arxiv.org/html/2608.15939v1) |
| H15 | PatchKV (2026 preprint) | Splits edited prompts into exact prefix, edit region and position-aligned suffix, then selectively recomputes affected blocks and reloads the rest with approximate quantization/position repair. Useful for separating workload edit shapes. Its QA accuracy comparison addresses approximate reuse of changed dependencies. [Paper](https://arxiv.org/abs/2609.26219) |
| H16 | CacheReforge (2026 preprint) | Associates stale KV with adapter versions and uses calibrated tail influence to choose direct reuse or bounded recomputation. This motivates explicit model generation in a cache key. v16 keeps one sealed model generation and faults on identity changes. [Paper](https://arxiv.org/abs/2609.30884) |
| H17 | VeriCache (2026 preprint) | Drafts using compressed KV and verifies tokens with full KV, overlapping transfer and compute to recover full-cache outputs. An exact-output route for compressed caches would need additional memory/transfer accounting. v9e's BF16 fixture parity is against its own reference and deserves separate qualification against FP32 behavior. [Paper](https://arxiv.org/abs/2605.17613) |
| H18 | Cache Engineering for Agents (2026 preprint) | Exposes drop and reposition operations and observes that cache operation history can make identical tokens lead to different attended states. A bounded-state experiment should log logical prefix, physical validity and the operation history independently. Its direct KV manipulation has broader semantics than the v14 exact-prefix tracker. [Paper](https://arxiv.org/abs/2610.28577) |
| H19 | CacheBlend (2024 preprint, revised 2025) | Selective recomputation restores cross-chunk dependencies when cached documents appear outside an unchanged prefix. This identifies the semantic reason to avoid reusing apparently identical suffix tokens after a prefix edit. [Paper](https://arxiv.org/abs/2405.16444) |
| H20 | SGLang (2024, NeurIPS) | RadixAttention matches and shares KV prefixes across structured language programs. It is a clear predecessor for exact prefix reuse and a reason to include a cache-enabled resident baseline. v14/v16 use one bank and reuse only one conversation at a time. [Paper](https://arxiv.org/abs/2312.07104) |
| H21 | Prompt Cache (2024, MLSys) | Declares reusable prompt modules and arranges their positions to reuse precomputed attention states. Repeated system/schema content was already a cache opportunity on GPU and CPU. Its modular prompt semantics differ from matching token IDs at the same positions. [Paper](https://arxiv.org/abs/2311.04934) |
| H22 | Efficient Memory Management for Large Language Model Serving with PagedAttention (2023, SOSP) | Uses KV block tables for sharing and reduced fragmentation in continuous serving. This defines the distinction between reusing work and allocating memory dynamically. The v9d scratch reservation and allocated KV capacity remain fixed across prefix hits. [Paper](https://arxiv.org/abs/2309.06180) |
| H23 | DéjàVu (2024, ICML) | Streams and replicates KV to recover after failures in cloud GPU serving. It is direct precedent for fault recovery via retained inference state. Single-bank recovery has a stricter budget and requires proving safe preservation without a replica. [Paper](https://arxiv.org/abs/2403.01876) |
| H24 | Elastic KV Cache for LLM Serving (2026 preprint) | Reclaims worst-case activation reserve during decode via CUDA virtual memory. The paper reports little benefit in its setup once chunked prefill is used. This is a reason to evaluate a simple single-bank invalidation policy before claiming value from more complex memory management. [Paper](https://arxiv.org/abs/2608.23658) |
| H25 | Do OS abstractions make sense on FPGAs? (2020, OSDI) | Coyote integrates virtual memory and protected multiplexing in a host-linked FPGA shell. General FPGA isolation already exists. v16's Linux model-weight mappings and lock protect a narrower boundary, with privileged raw access and physical faults outside the guarantee. [Paper](https://www.usenix.org/conference/osdi20/presentation/roscoe) |
| H26 | Sharing, Protection, and Compatibility for Reconfigurable Fabric with AmorphOS (2018, OSDI) | Morphlets provide process-like protection and spatial/temporal multiplexing for mutually distrustful fabric users. This helps separate the scope of a single-owner cache contract from tenant and bitstream isolation. [Paper](https://www.usenix.org/conference/osdi18/presentation/khawaja) |
| H27 | FINN-Tro (2026 preprint) | A counter-triggered alteration to a compiled FINN datapath can harm outputs while preserving similar runtime. The studied targets are image classifiers. It is a methodological precedent for long, stateful verification traces and an explicit trusted-bitstream assumption in a decoder study. [Paper](https://arxiv.org/abs/2609.26824) |
| H39 | Transactional KV Caching for Speculative Decoding under Paged KV Memory (2026 preprint) | TransKV places provisional draft KV in a packed buffer and commits only accepted tokens to the paged cache. Its memory and GPU experiments address branching concurrency. The proposed K26 experiment instead relies on provable in-place write disjointness to preserve the earlier committed range within a single bank. [Paper](https://doi.org/10.36227/techrxiv.177101038.80960856/v1) |
| H40 | CXL-SpecKV (2026, ACM FPGA) | Uses FPGA compression, address translation and cache management on a CXL memory tier, with prefetch predictions for data-center GPUs. FPGA-managed KV and speculative optimization already have precedent. The AXI/shared-DDR experiment asks whether a device command boundary can support exact reuse following a cooperative application cancellation. [Paper](https://arxiv.org/html/2512.11920) |

## Alternative devices, energy methods, and encoder lineage

| ID | Paper | Finding and relevance |
|---|---|---|
| H28 | MELTing Point (2024) | Automates latency, memory, quality and energy measurements on Android, iOS and Jetson. Quantization and sustained thermal behavior matter materially. Report fixed-work, sustained and application results separately on KR260. [Paper](https://arxiv.org/abs/2403.12844) |
| H29 | PowerInfer-2 (2024 preprint) | Splits neuron clusters between phone CPU and NPU and overlaps I/O through a segmented cache. It demonstrates a different way to exceed resident memory, with different model, storage and quality constraints from K26. [Paper](https://arxiv.org/abs/2406.06282) |
| H30 | Characterizing Mobile SoC for Accelerating Heterogeneous LLM Inference (2025, SOSP) | HeteroInfer uses unified memory for fast GPU/NPU synchronization and jointly uses accelerator bandwidth. The useful comparison is the synchronization cost across agents sharing state. K26's MMIO, AXI and device-memory path must be measured directly. [Paper](https://arxiv.org/abs/2501.14794) |
| H31 | LLM Inference at the Edge (2026 preprint) | Twenty warmed runs with a fixed Qwen2.5-1.5B prompt reveal thermal throttling on phones and different performance limits on Hailo and laptop GPU. A paired KR260 experiment should record temperature and alternate arms across blocks. The published hardware ranking covers one prompt/model setup. [Paper](https://arxiv.org/abs/2603.23640) |
| H32 | MobiBench (2026 preprint) | A common llama.cpp suite pairs latency, accuracy, memory and battery metrics across devices. It supports using the same task traces for resident software and FPGA comparison, with separate accounting for quantization and backend differences. [Paper](https://arxiv.org/abs/2609.13159) |
| H33 | When NPUs Are Not Always Faster (2026 preprint) | Controlled stage masking attributes end-to-end differences to communication, quantization, compute and scheduling. The studied mobile NPU gives only modest decode gains. System One should attribute wall time to software verification and transfer as well as prefill and decode. [Paper](https://arxiv.org/abs/2605.27435) |
| H34 | Understand and Accelerate Memory Processing Pipeline for Large Language Model Inference (2026, ICML) | Profiles memory-processing steps in long-context methods and offloads irregular memory operations from GPU to FPGA. It reinforces the need to measure selection, movement and application of memory state separately. The evaluation uses a discrete GPU/Alveo system. [Paper](https://proceedings.mlr.press/v306/he26ab.html) |
| H35 | MLPerf Power (2025, HPCA) | Demonstrates repeatable energy measurements across varied device scales. Use simultaneous quality, wall-time and physical input-energy results at one declared boundary. Model-stage power and total board energy have distinct meanings. [Paper](https://arxiv.org/abs/2410.12032) |
| H36 | Part-time Power Measurements (2024 revision) | External measurement and workload microbenchmarks reveal under-sampling in some NVIDIA power telemetry. This motivates a load-step and fresh-sample study for the K26 sensor. Its measured NVIDIA behavior is specific to that hardware. [Paper](https://arxiv.org/abs/2312.02741) |
| H37 | FTRANS (2020) | Block-circulant compression reduces transformer storage and matches a hardware accelerator to that representation. It is a relevant ancestor to the repo's compressed encoder path and a reminder that layout gains must be compared at measured model quality. [Paper](https://arxiv.org/abs/2007.08563) |
| H38 | NPE (2021) | Uses a programmable FPGA overlay for BERT-style linear and nonlinear work and demonstrates conversational latency with lower reported power than its CPU/GPU controls. It provides a useful comparison for the earlier encoder task head and layer operators. Autoregressive decode and cache recovery have different runtime behavior. [Paper](https://arxiv.org/abs/2104.06535) |

## Repository evidence and experiment boundary

The tracked v9d source implements eight-token prompt groups with two-query attention, FP32 KV storage and a 1,024-token profile. The tracked v9e candidate doubles context to 2,048 with BF16 KV in the same reservation and FP32 arithmetic. Commit `04d6ab2` records 4,112 causal checks against the v9e reference and short/410-token matching outputs versus v9d. The saved candidate evidence includes one correct 1,454-token prompt at 77 seconds. The ABI2/chunked-copy candidate has two saved cold timings of 6.949 and 6.855 s, with earlier SIGBUS failures retained. These are finite candidate qualifications and the last saved status records restoration of v9d. [Board record](../../BOARD_STATUS.json), [hardware report](2026-10-21-claude-hardware-recommendation.md).

The v14 cached-history result makes optimized history essential to a fair comparison. For the 104 common fitting steps, v9d evaluated 4,144 JSON-state versus 6,202 history tokens, compared with logical counts of 13,416 versus 56,290. The cached experiment preserves references and fixes incoming traces independently of outputs. These results establish reduced prefill work on that replay and a context-capacity effect. [Prefix comparison](2026-10-22-v9d-prefix-comparison-v14.md).

The v16 service combines model ownership, startup hashing and single-bank prefix reuse. Its finite three-arm timing reports 5.599, 3.889 and 3.155 s across six requests per arm. The lease protects coordinated weight access and the scratch tag binds host metadata to a scratch instance. In source, each synchronous decoder call polls AP_DONE/status after checking AP_IDLE at issue. The tag is host-written and the reported work counters are updated in the host runtime after returns. These are useful signals for request accounting. A device-level completion claim would additionally require evidence about AXI transactions. [v16 report](2026-10-22-sealed-verification-prefix-v16-results.md), [runtime](../../src/sysone/v2/qwen_fpga_runtime_v16.py), [prefix tracker](../../src/sysone/v2/prefix_cache_v14.py).

## Hardware reviewer position

A tractable systems question is whether v9d can retain a previously committed exact prefix after a cooperative cancellation at a verified command boundary, using its existing single DDR KV bank and preserving cold-reference results. H14 already supplies logical rollback semantics and a strong same-token audit. The contribution would be the minimum physical conditions for one-bank reuse and a measured recovery-work and latency tradeoff, with H23 as a replication-based comparison.

The first feasibility check is generated-RTL co-simulation with delayed AXI write responses. Verify that reported completion implies retirement, that each issued command only writes KV at or beyond the conservative shared prefix, and that attention masks prevent abandoned suffix data from affecting visible tokens. If completion evidence is available, inject deterministic cancellations after selected layer commands and before tool publication. Preserve only aligned committed positions guaranteed untouched under every admitted interruption. Treat uncertain completion and identity mismatch as faulted. Fail-cold means discard reusable state and resume only after the existing verified drain/restart path.

Compare always-invalidate and retained-prefix recovery using identical resumed requests and a deliberately stale positive control. Sweep cancellation point and common-prefix length, including zero, short and near-capacity. Require identical request IDs, generated IDs, relevant logits where observable and permitted effects versus the cold reference. Add independent address/write traces or offline retained-range digests. Report re-evaluated tokens, resume TTFT, cancellation-to-ready time and wall time. Use no extra full-size KV allocation. If the drain property cannot be verified, limit the experiment to fully completed requests and characterize representation × reuse on a new held-out workflow. That characterization needs a resident ARM baseline and task-level accuracy/coverage to add to v14.

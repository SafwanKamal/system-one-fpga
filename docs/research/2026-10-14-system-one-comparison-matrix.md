## C. Corrections and comparison rules

1. **Common fabric, different system:** [AMD DS987](https://docs.amd.com/r/en-US/ds987-k26-som/Programmable-Logic) lists K26 117,120 LUT, 234,240 FF, 144 BRAM36, 64 URAM and 1,248 DSP. [KR260 DS988](https://docs.amd.com/r/en-US/ds988-kr260-starter-kit/Product-Details) and [KV260 DS986](https://docs.amd.com/r/en-US/ds986-kv260-starter-kit/Product-Details) establish K26 kits with 4 GB DDR. Carrier, boot, cooling, OS, clock configuration and contention differ. The System One implemented part is known; do not infer the papers' exact speed grade. Shared capacity does not make runtime performance equivalent.
2. **Bandwidth discrepancy:** P1 states 19.2 GB/s; P2's table states 17.1 GB/s for KV260. Do not average these or treat either as a measured service rate for our runtime. P1's four 300 MHz128-bit interfaces have a 19.2 GB/s aggregate interface ceiling. Ours has 3.2 GB/s at 200 MHz. Confirm DDR configuration and actual payload service independently in any future experiment.
3. **P2 table caveats:** its MEADOW row lists 845 DSP / 2034 BRAM, whereas MEADOW's own §6.1 says 845 BRAM / 2034 DSP. Use the primary counts. P2's total 136,721 FF is labeled 28%; divided by AMD's 234,240 FF it is 58.37%. Retain the absolute count, flag the percentage, and avoid silently correcting the author's source. Its LlamaF PPL 8.89 differs from the primary 7.09 protocol; the latter is recorded here.
4. **P6 identity:** the primary case study uses PYNQ-Z1/Cortex-A9 and Q3_K×Q8_K, not a Cortex-A53/Kria W4A16 design. Later summaries vary; do not copy them into an architecture claim.
5. **Numbers with different scopes:** P1 host console timing includes prompt submissions in both timer and token count. P2 has separate kernel, synchronization, prefill/head and generation timers. P7 reports throughput at different step counts. A3 measures a layer. P5/P9 include simulated configurations. None can be treated as the same unit as our saved encoder request.
6. **Fair comparison:** require same model/checkpoint/tokenizer, quantization/calibration, batch, input length distribution, context/output count, attention mask, host tasks, clock and timing/energy boundary. If matching is impossible, compare mechanisms and constraints rather than ratios. Do not linearly rescale sequence-length latency: attention, reuse, pipeline fill and padding change nonlinearly.
7. **Quality and reproducibility:** separate model accuracy from arithmetic parity; measured rails from tool estimates; physical timing from a requested clock; downloadable source from a reproduced artifact. “NR” is an evidence gap to resolve, not a reason to fill a cell using another workload.

# Research review of interruption recovery, action assurance, and measurement

November 4, 2026. This targeted screen covers 39 distinct research papers and research reports. I reviewed primary-source abstracts or excerpts for each entry and selected implementation, evaluation, or theory sections for papers closest to the proposed work. Preprints are identified where relied on as such. The numbered entries count one work per title. The two unnumbered disclosures and artifacts are supplementary leads. No result was independently reproduced in this review.

## Repo evidence relevant to these papers

The comparison isolates the verification and caching steps in separate modes. It covers neither partial-request recovery nor energy. A completion and memory-visibility argument must follow the generated HLS adapters, interconnect, and DDR access path. The encoder's typed200 drain observer is a different implementation. ## KV recovery and accelerator transaction boundaries

**A01. DéjàVu: KV-cache Streaming for Fast, Fault-tolerant Generative LLM Serving (2024).** A streaming KV library enables state replication for failure recovery alongside prompt/token disaggregation and microbatch swapping. This is direct precedent for retaining inference progress across failures. A board with one DDR KV bank and no standby must derive reuse from trustworthy surviving bytes and known write boundaries instead of restoring a separate replica. [Author paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2024/06/7085_d_j_vu_kv_cache_streaming_for_.pdf)

**A02. Concordia: JIT-Compiled Persistent-Kernel Checkpointing for Fault-Tolerant LLM Inference (2026 preprint).** A device-resident kernel and PTX/SASS instrumentation insert checkpoint and pause hooks below the serving framework. This makes device-owned recovery progress clear prior art. The repo can restrict its state to causally complete KV on a fixed-address bank, with a separate completion and DDR-visibility contract. [Author preprint](https://arxiv.org/abs/2606.23521)

**A03. Towards Resiliency in Large Language Model Serving with KevlarFlow (2026 preprint).** This serving architecture addresses long recovery paths caused by restarting a worker and reloading large model weights. System One should distinguish retaining sealed weights from retaining KV. A latency result must hold the model-verification and reload policy fixed across recovery strategies. [Author preprint](https://arxiv.org/abs/2601.22438)

**A04. LUMEN: Coordinated Failure Recovery for Distributed LLM Serving (2026 preprint).** Coordinates checkpoint placement, routing of interrupted requests, and capacity restoration during model reload. The cluster evaluation tests load-aware recovery. On KR260 the corresponding decision is when the existing single bank is eligible for another request and how much prefill it can avoid. [Author preprint](https://arxiv.org/abs/2606.17787)

**A05. Fast State Restoration in LLM Serving with HCache (EuroSys 2025).** Stores intermediate activations and reconstructs KV, trading I/O against recomputation while addressing different save and restore traversal orders. It motivates the always-recompute comparison and a recovery-traffic ledger. The proposed FPGA baseline is narrower and reuses resident, committed KV rows directly. [Author paper](https://chenyoumin1993.github.io/papers/eurosys25-hcache.pdf)

**A06. RISK-KV: Quality-Aware Selective KV Cache Reconstruction for Distributed LLM Inference (2026 preprint).** Explores selective reconstruction in a cache transfer or replay tradeoff. This is a warning against claiming novelty for partial reconstruction alone. An exact committed prefix should be scored against the original execution order and kernel, with separate numerical controls for any changed arithmetic order. [Author preprint](https://arxiv.org/abs/2610.29544)

**A07. CacheReforge: Bounded Recovery for Stale KV Caches under Evolving Adapters (2026 preprint).** Models mixed adapter versions at layer level and calibrates when selective repair approximates fresh behavior. It illustrates why state validity needs model and adapter identity. System One's initial recovery should treat an identity transition as a cold boundary and preserve an exact same-generation contract. [Author preprint](https://arxiv.org/abs/2609.30884)

**A08. EPOCH: Enabling Preemption Operation for Context Saving in Heterogeneous FPGA Systems (2025 preprint).** Captures FPGA primitive state and reports frame-granular context save and restore on Zynq-XC7Z020. This preempts general claims for preserving FPGA accelerator context. The candidate here would preserve only a verified semantic frontier in resident DDR, avoiding capture of HLS pipeline, register, and BRAM state. [Author preprint](https://arxiv.org/abs/2501.16205)

**A09. GPU Checkpoint/Restore Made Fast and Lightweight (FAST 2026).** Separates data and control paths for application-transparent GPU checkpointing and supports incremental checkpoints. The evaluation reports reduced checkpoint sizes and recovery latency relative to other GPU mechanisms. The transfer is to benchmark metadata/control separately from data-copy cost and to charge incremental overhead on successful requests too. [Conference paper](https://www.usenix.org/conference/fast26/presentation/zeng)

**A10. GPUReplay: A 50-KB GPU Stack for Client ML (ASPLOS 2022).** Records accelerator operations through a full stack and replays them through a much smaller embedded GPU stack, with mechanisms for replay divergence. Replay can simplify a recovery oracle if command addresses, inputs, and ordering are explicit. This is prior art for accelerator command replay, with a different goal from preserving application state after interrupted writes. [Author paper](https://arxiv.org/abs/2105.05085)

**A11. Safely Preventing Unbounded Delays During Bus Transactions in FPGA-based SoC (FCCM 2020).** Demonstrates FPGA-side timeout and safe AXI failure handling in a Zynq setting. It is the closest older hardware mechanism and makes a timeout monitor alone insufficient as a contribution. A decoder experiment needs to show precisely which previously committed rows survive and when new commands can safely reuse the bank. [Author paper](https://retis.sssup.it/~f.restuccia/papers/Restuccia-FCCM20.pdf)

**A12. Scalable AXI4 Transaction Monitoring for Mixed-Criticality SoCs: From Phase-Level Precision to ID-Level Efficiency (2026 preprint).** Compares phase, channel, and transaction-ID tracking and uses cut-and-drain isolation after faults. Reports a large fault-injection campaign on a RISC-V SoC. System One should either reuse comparable principles or demonstrate why a smaller monitor suffices under its specific port and command discipline. This work's bus liveness result does not itself certify a KV prefix. [Author manuscript](https://arxiv.org/html/2608.30435v1)

**A13. XRAY: Detecting and Exploiting Vulnerabilities in Arm AXI Interconnects (DATE 2025).** Generates AXI traffic to test system-level interconnect properties, with FPGA demonstrations of dropped transactions, corruption, and leakage. Motivates checks beyond protocol compliance and fault injection around posted or late writes. The repo's cooperative-driver threat model should state clearly whether malicious IP is within scope. [Author paper](https://www.shwetashinde.org/publications/xray_date25.pdf)

**A14. AXI-IC^RT: Towards a Real-Time AXI-Interconnect for Highly Integrated SoCs (published online 2022).** Reorganizes buffered transactions and arbitration to reduce priority inversion in shared interconnects. A watchdog that creates a local result can be independent of DDR progress. A bound for returning that result through shared interconnects needs separate service assumptions. [Institutional paper record](https://pure.york.ac.uk/portal/en/publications/axi-icrt-towards-a-real-time-axi-interconnect-for-highly-integrat/)

**A15. CURE: A Security Architecture with CUstomizable and Resilient Enclaves (USENIX Security 2021).** Demonstrates hardware-assisted isolation, including exclusive assignment of peripherals and other resources on a RISC-V SoC. This is a contrast to a coordinated Linux DMA lease. A v16-derived design can claim its scoped single-owner lifecycle and measured faults, with kernel, raw MMIO, and unrelated DMA assumptions explicit. [Conference paper](https://www.usenix.org/conference/usenixsecurity21/presentation/bahmani)

## Atomicity and recovery semantics

**A16. Using Crash Hoare Logic for Certifying the FSCQ File System (SOSP 2015).** Adds crash conditions and recovery procedures to the proof judgment and verifies the implementation under repeated crashes. The transfer is to specify the state after interruption at each phase, including a second fault during recovery. For volatile DDR the modeled failure is loss of service progress while the relevant memory, reset, and lease assumptions still hold. [Author paper](https://pdos.csail.mit.edu/6.828/2018/readings/fscq-sosp15.pdf)

**A17. All File Systems Are Not Created Equal: On the Complexity of Crafting Crash-Consistent Applications (OSDI 2014).** Uses application crash testing to expose dependence on persistence and ordering properties of lower layers. Similarly, fault injection should check assumptions about visibility across the HLS AXI master, interconnect, DDR, and next reader. A host metadata update cannot establish that ordering by itself. [Conference paper](https://www.usenix.org/conference/osdi14/technical-sessions/presentation/pillai)

**A18. Linearizability: A Correctness Condition for Concurrent Objects (TOPLAS 1990).** Formalizes operations taking effect at some point between invocation and response and supports compositional reasoning. Model cache validity publication and simulated action release as separate objects. The cache publication edge must follow the write-visibility condition, and the action's acceptance point belongs at its authoritative sink. [Author paper](https://www.cs.cmu.edu/~wing/publications/HerlihyWing90.pdf)

**A19. Implementing Linearizability at Large Scale and Low Latency (SOSP 2015).** RIFL uses unique RPC identifiers and completion records to make retries safe while coordinating record lifetime and data migration. An analogous simulated inspection sink needs session/request/action IDs and recorded consumption if a duplicate may arrive. A lost acknowledgment requires reconciliation or an unknown outcome. [Conference paper](https://sigops.org/s/conferences/sosp/2015/current/2015-Monterey/printable/126-lee.pdf)

**A20. Implementing Remote Procedure Calls (TOCS 1984).** Uses call identifiers and duplicate suppression. A caller that sees a communication exception can still lack knowledge of execution. This supports distinguishing local timeout, dispatched action, and acknowledged effect in the maintenance adapter. [Author paper](https://www.cs.cmu.edu/~15712/papers/birrell84.pdf)

**A21. The Chubby Lock Service for Loosely-Coupled Distributed Systems (OSDI 2006).** Uses sequencers for the protected service to reject work issued by expired lock holders. Generation numbers and session tags likewise matter at the component that accepts a command. A host-side ownership check alone cannot fence already-issued bus traffic. [Conference paper](https://www.usenix.org/legacy/event/osdi06/tech/full_papers/burrows/burrows_html/index.html)

**A22. On Optimistic Methods for Concurrency Control (TODS 1981).** Separates speculative read and compute from validation and update, comparing serial and parallel validation. This is foundational for state-bound action commit. Separately, the single-bank KV recovery design needs a precise write set and a conservative fallback when that set or identity becomes unknown. [Author paper](https://www.eecs.harvard.edu/~htk/publication/1981-tods-kung-robinson.pdf)

## Assured action release and industrial control

**A23. Stale Does Not Mean Unsafe: Guard Precision for Tool-Using LLM Agents under Infrastructure State Races (2026 preprint).** Uses frozen paired proposal replays, authoritative versus visible state, injected races, and epoch, read-set, and predicate guards. Freshness guards blocked 92–95% of benign races in the reported setting. An incomplete predicate admitted precisely the corresponding fault family. This is direct prior art for the comparison in the October maintenance plan. A distinctive experiment needs physical commitment and timing semantics or a different workload question. [Author manuscript](https://arxiv.org/html/2609.29522v1)

**A24. Atomix: Timely, Transactional Tool Use for Reliable Agentic Workflows (2026 preprint).** Separates a transaction's sealed effect footprint from per-resource progress frontiers that establish when earlier conflicts can no longer arrive. Reports improved fault recovery and controlled release of irreversible effects. This directly challenges the originality of combining agent-side commit and drain, while leaving a tightly scoped FPGA memory frontier and hardware sink case to establish. [Author preprint](https://arxiv.org/abs/2602.14849)

**A25. LIR+LVM: Bounded execution of LLM-generated code on microcontrollers (2026).** A structured IR lowers to bytecode for a step-limited, capability-gated VM deployed on three MCU targets. The publisher abstract reports testing 8,000 adversarial payloads. A bounded maintenance DSL and capability check already have a close implementation precedent. Progress-independent timeout publication and live ownership qualification are separate claims. [Publisher abstract and highlights](https://www.sciencedirect.com/science/article/pii/S1383762126003310)

**A26. VIGIL: Defending LLM Agents Against Tool-Stream Injection via Verify-Before-Commit (ACL 2026).** Uses intent-grounded verification of speculative agent behavior and evaluates on 959 tool-stream injection cases. It is direct prior art for proposal verification before committing effects. The FPGA question concerns faults, delayed traffic, and authoritative state under a declared trust model. [Conference paper](https://aclanthology.org/2026.acl-long.443/)

**A27. AgentSpec: Customizable Runtime Enforcement for Safe and Reliable LLM Agents (ICSE 2026).** Implements triggers, predicates, and enforcement rules for code, embodied agents, and driving examples. The paper reports millisecond-scale software overhead, so a PL path needs an optimized software comparator and a fault-independence result rather than just a fast comparator circuit. [Author paper](https://cposkitt.github.io/files/publications/agentspec_llm_enforcement_icse26.pdf)

**A28. Progent: Securing AI Agents with Privilege Control (2026 revision).** Checks tools and arguments through deterministic symbolic privilege rules and evaluates attacks and utility in agent benchmarks. The relevant measurement is both forbidden releases and correct work blocked. The repo can use fixed operator-defined permissions and evaluate changing authoritative conditions separately. [Author manuscript](https://arxiv.org/abs/2504.11703)

**A29. Defeating Prompt Injections by Design (CaMeL, 2025 preprint).** Controls information and execution flow with a protective layer and capabilities rather than trusting the planner's behavior on untrusted inputs. Its model supports scoped security and utility results. The repo can similarly keep sensor observations and release authority outside the model, then define provenance and trust before claiming enforcement. [Author preprint](https://arxiv.org/abs/2503.18813)

**A30. Enforcing Temporal Constraints for LLM Agents (Agent-C, 2025 preprint).** Enforces temporal safety specifications over agent actions and evaluates formal conformance and task utility separately. It establishes prior art for enforcing action prerequisites and order. The hardware-specific experiment must make the operational clock, traffic retirement, and sink handshake explicit. [Author preprint](https://arxiv.org/abs/2512.23738)

**A31. Runtime Enforcement of Programmable Logic Controllers (2021 preprint).** Synthesizes timed edit automata that suppress, correct, or autonomously emit events under a declared controller property. A water treatment case study tests corrupted controllers. A proposed report/inspection gate is a narrower event protocol and should state that it does not take over continuous plant control. [Author preprint](https://arxiv.org/abs/2105.10668)

**A32. LLM4PLC: Harnessing Large Language Models for Verifiable Programming of PLCs in Industrial Control Systems (ICSE SEIP 2024).** Combines generation with grammar, compilation, and model-checking feedback on a manufacturing testbed. The paper reports generation success rising from 47% to 72%. This is a design-time program assurance comparator. System One's target is per-request decisions conditioned on live readings, with a separate runtime issue boundary. [Author paper](https://arxiv.org/abs/2401.05443)

**A33. SemaPLC: A Project-Grounded, Verification-Gated Agent Harness for PLC Code Generation (2026 preprint).** Separates successful compilation from behavior across scan cycles and tests an approach to prevent edits from retaining obsolete verification. Motivates binding verification to exact policy and model versions. Its generated PLC program lifecycle is distinct from a serialized maintenance request on an embedded inference service. [Author preprint](https://arxiv.org/abs/2608.18565)

**A34. Shield Synthesis: Runtime Enforcement for Reactive Systems (2015).** Synthesizes hardware-style output shields that intervene when needed to enforce a limited set of safety properties. The useful transfer is to prove the small critical boundary and quantify unnecessary interference. Model interpretation and plant correctness require separate evidence. [Author paper](https://arxiv.org/abs/1501.02573)

**A35. ModelPlex: Verified Runtime Validation of Verified Cyber-Physical System Models (journal 2016).** Derives monitors to establish when observations stay within the verified model and invokes fallback when they do not. This motivates using trusted receipts and explicitly modeling measurement age, fault, and update races. A discrete simulator supports policy properties within its world model. [Author paper](https://logic.kastel.kit.edu/ap/pub/modelplex-long.pdf)

**A36. SOTER: A Runtime Assurance Framework for Programming Safe Robotics Systems (DSN 2019).** Composes unverified advanced controllers, certified fallback controllers, and formal safety specs. Tests both simulation and real drones. This supports using a trusted baseline as a first-class comparison and exposing the cost of falling back. The maintenance candidate can stop or request clarification in its initial reporting-only domain. [Author paper](https://arxiv.org/abs/1808.07921)

## Physical validation and measurement

**A37. MLPerf Power: Benchmarking the Energy Efficiency of Machine Learning Systems from Microwatts to Megawatts for Sustainable AI (HPCA 2025).** Couples workload, quality, performance, and physical measurement across hardware scales. Specify a whole-board boundary and use energy per correct on-time completion over all attempted requests if the sensor cadence and study design support it. A gate's isolated LUT count and cycle bound answer a different question. [Author paper](https://arxiv.org/abs/2410.12032)

**A38. Part-time Power Measurements: nvidia-smi's Lack of Attention (SC 2024).** Compares built-in telemetry with an external meter and finds that telemetry can miss substantial portions of transient workloads. Run step-response and fresh-sample tests on the actual KR260 sensor before attaching phase-energy claims to short commands. Its GPU-specific correction cannot calibrate the board. [Author paper](https://arxiv.org/abs/2312.02741)

**A39. Condition Monitoring of Bearing Damage in Electromechanical Drive Systems by Using Motor Current Signals of Electric Motors: A Benchmark Data Set for Data-Driven Classification (2016).** Generates fault-labeled bearing data using a test rig and compares data-driven diagnostic classification. Useful for constructing realistic observation histories and fault profiles in a simulator. It supplies neither human request labels nor authority to infer when a report or inspection must be released. [Conference paper](https://www.papers.phmsociety.org/index.php/phme/article/download/1577/542)

## Supplementary sources outside the paper count

- The **FPGA-resident guardrail fabric** defensive disclosure explicitly proposes hardware-interlocked release of tool requests with identity and state binding. It narrows any broad mechanism claim even though this screen found a disclosure rather than validated board performance. [Disclosure](https://www.tdcommons.org/dpubs_series/12215/)
- The **kvpack** source project describes authenticated, compatible, bitwise-exact state restore after a crash using an artifact format and shadow-state installation. A generic claim of exact crash recovery would overlap. A single fixed FPGA bank with no KV replica and a hardware-qualified prefix watermark is the narrower candidate. [Author repository](https://github.com/High-Performance-AI-Lab/kvpack)

## Design implications for System One

For a single-bank study, keep the proposed guarantee within a known model, clock and boot generation. Track a prefix watermark at complete token-group boundaries. Invalidate the suffix metadata before launching the first write that could overwrite any previously advertised row, including when switching to a prompt with a shorter shared prefix. Extend the watermark only after every layer has completed for the group, all relevant masters and buffered transactions have retired, and the earlier writes are visible to the next reader. Isolate persistent metadata publication from scratch writes, restart temporary model state, recompute final logits, and bind recovery to exact tokens and board identity. A service restart would additionally need an independently retained trusted watermark. A process-local tracker can support cooperative cancellation under the same owner.

Inject failures before launch, after a completed group, between layer commands, and while AW, W, B, AR, or R is pending. Test a short mismatched prefix, delayed B or RLAST, stale completion identifiers, reset, ownership change, and a repeated failure during recovery. Unknown writers or reset state require quarantining the bank until safe reinitialization. A software test between qualified completed commands can establish whether avoiding replay matters for realistic workload traces. On-board, in-flight faults plus verified drain and visibility are needed to extend the claim to interruption while commands are active. An end-to-end restart claim must charge any time spent waiting for drain and re-establishing ownership.

Compare always replay, v16's clean-call reuse and fail-cold behavior, and the in-place candidate. Separate opportunities created by workload (for example, structured-output rejection or cancellation) from the injection rates used to test correctness. Report committed-prefix retention, wrong reuse, next-correct-result time, prefill work, recovery overhead on successful requests, and extra physical storage. An effect gate would be a separate contribution and should benchmark the optimized ARM checker against PL using frozen proposal and event traces.

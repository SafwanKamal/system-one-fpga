# Same-stage ADD_SKIP saturation experiment

Separate candidate `rtl/v2/candidates/typed200_clamp` changes only
`encoder/add_skip_engine.sv` from frozen `typed200_profile_cache`. The parent
placed worst path was rounded skip to residual output saturation: +0.417 ns
setup at 5 ns, 10 levels including six CARRY8s and 4.219 ns data delay. The
parent failed the preserved +0.500 ns routing gate and remains unrouted.

Both asymmetric [-32767,32767] clamps are expressed as sign-extension and
low-bit-zero reductions. Positive values clamp when high bits are nonzero;
negative values are in range only if the high bits are all ones and the low
15 bits are nonzero. This handles -32768 exactly. The residual sum is still
signed 17 bits. No product, 26-bit rounding overflow, dynamic shift, pipeline
register, reset, valid/address/control, output cycle or deadline logic changes.

## Functional proof

`build/v2/typed200-clamp-formal-v5/receipt.json` records two actual-source proofs:

- Combinational equality for **all 2^26 rounded values and 2^16 residuals**, with
  no product-reachability or legal-shape assumption. The proof lane is extracted
  from each actual old/new arithmetic block, rather than reimplementing the
  proposed expression separately.
- Whole-engine equivalence: **966 proven equivalence points / zero unproven**,
  including every public output and matched internal state. Corresponding initial
  state, one sampled clock and two-state semantics are the scope. Actual modules
  use READ_LATENCY=3, MAX_TOKENS=128 and BUFFER_ADDRESS_WIDTH=14. Package import
  normalization in proof copies substitutes the verified default READ_LATENCY=3;
  candidate sources are unchanged. There are no protocol, shape, multiplier,
  shift or input-data restrictions. This is not analog reset/CDC or physical proof.

Earlier attempts are preserved. v1's generator asserted an incorrect port count
before tool invocation. v2 needed formal-check lowering for the pinned Yosys.
v3 passed arithmetic but duplicated multiply histories reached 1.41 million SAT
variables/4.12 million clauses at base eight; its exact solver process was
identified and stopped at approximately 1.54 GB working set. v4's state-point
approach still re-proved identical multiply bit cones and was stopped after
identity verification. v5 optimizes common cones **after** equiv_make and proves
all the same state points. Candidate RTL did not change. The abandoned v3
history-unrolling formulation used a first-reset/eight-clock fill condition;
v4/v5 instead prove corresponding-state equivalence under the initial-state

The new [worst path](../../build/v2/typed200-clamp-ooc-v2/clamp/rounded-paths.rpt)
runs from rounded_reg[6][23] to out_data_reg[100]/R. The reduction/mux network
improves mapped logic delay but increases estimated wire delay enough to lose
overall. Both cones retain 10 levels. This rejects this particular Boolean
decomposition as a timing optimization; it does not establish that all clamp
architectures fail or that the OOC wire estimates predict a routed delta.
Reduced resources alone do not justify a new hour-scale full-design run.

The strongest next local experiment is to move the first saturation into the
existing rounded-skip register stage, storing a clamped INT16 skip there. The
output stage then contains only the 17-bit residual add and final clamp, with
no added cycle. This is a different candidate and is **not implemented here**.
Preserve exact 26-bit rounding before clamping, rename the changed-semantic
register so an equivalence tool does not assume old/new rounded state matches,
and prove public output/cycle correspondence with the proper stage relation.
Inspect the rounding/shift stage as well as the output stage: moving logic can
create a worse preceding-stage limit. A further pipeline stage is a separate,
explicitly cycle-changing option that needs new native/deadline budgets.

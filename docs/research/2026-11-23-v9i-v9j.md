# v9i go/no-go and the v9j outcome (2026-11-23)

**Recommendation: pilot v9i (RC1.4) on the KR260. Drop v9j as designed.** v9i fits with room to
spare, meets timing, is bit-exact with v9h in a full-decoder prefill C-sim, and has a packaged,
dry-run pilot bundle with a cross-checked analyser. v9j keeps P=4 attention but its narrow
multiplier added area instead of saving it, and the projected decoder alone exceeds the device.

### Limits

- **Exactness is C-sim only.** It shows source-level equivalence. The hardware uses the same Xilinx
  operators in the same order, so it should match too. The pilot checks this on the board: any
  token difference against RC1.3 is a NO-GO.
- **Tile boundary.** The full-decoder run did not cross the 256-row K/V tile. That boundary is
  covered by the attention-only probe (75,776 outputs, 0 differences).
- **Decode mode not separately simulated.** Single-token passes use the same code path as before
  the P change.
- **Dry-run tar hash.** The integration dry run produced `ef578873…`. The morning dry run, from the
  source checkout, produced `f41c9b50…`. Both passed. The tar is built from the local checkout, so
  the difference is likely from local inputs, such as the untracked `image.hex`. Confirm the
  hash on the day of the pilot from the exact checkout that will be installed.

## v9j: no-go

v9j = D3 + P=4 attention, with attention's fp32×bf16 multiplies replaced by Gemini's exact narrow
`mul_xb` (one 24×8 integer product, RNE, FTZ like the v9h hardware).

| | Result | Evidence |
|---|---|---|
| Multiplier exactness | `xmul_hls.hpp` matches the reference bit for bit over 501,743,616 pairs in both FTZ and IEEE (Gemini; re-run by Codex with MSVC and Vitis GCC) | `experiments/xmul/` |
| Attention exactness | Stock probe 75,776/75,776 exact vs D3. Directed subnormal fixture: only subnormal→zero differences (37,888 outputs), 0 unexpected; IEEE mode matches D3 exactly | `experiments/v9j/probe.md` |
| Schedule | Score and value loops stay at II=1 | `experiments/v9j/csynth.md` |
| Area (HLS) | Attention 46,586 → **96,200 LUT**, DSP 295 → 423; decoder 157,308 → 206,922 | same |
| Routed estimate | Decoder **≈ 133,338 LUT**, above the whole K26 (117,120) | same |
| Route | **Skipped** (gate was ≤ ~96k) | `experiments/v9j/route.md` |

**Why it grew:** the 56 FP32 `fmul` cores stayed (moved into the rescale pipeline), and each of the
128 new lanes carries about 390 LUT of unpack, normalize, round and FTZ logic around its DSP. A
v9j that fits would need the fmul bank shared, rounding hoisted out of the lanes (which gives up
bit-exactness by construction), or fewer lanes (which gives up the P=4 throughput). None of these
is a small change, and v9i already delivers the reclaim.

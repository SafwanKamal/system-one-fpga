# Prioritized System One experiment plan

Prepared 2026-10-14 America/Chicago. This is a **research plan**, not authorization or instructions to start builds/deployment. Only E0 (analysis of saved files) was performed during this review. The qualified 200 MHz package, 125 MHz recovery, 23 frozen sources, existing numerical fixtures, model bytes and reservation remain baselines.

Read the [review](2026-10-14-system-one-architecture-review.md), [matrix](2026-10-14-system-one-comparison-matrix.md) and [source registry](2026-10-14-system-one-sources.json) before implementation. Future candidates need separate source snapshots/app names and the existing admission process. Do not replay integration scripts, reroute rejected snapshots, rerun completed qualification helpers or recreate the deleted automation.

## 1. Ranking method

Evidence: **A** = direct qualified-source/hardware evidence; **B** = primary implementation precedent plus a compatible local mechanism; **C** = analytical extrapolation/unimplemented hypothesis. Benefit is a directional assessment or explicit bound, not an invented speedup. Effort S/M/L/XL means roughly analysis/software, local architectural change, multiple coupled engines, or a new execution/model platform; it is not a schedule commitment. Risk includes numerical, ABI, physical and validation risk.

Within encoder work, E2 is prioritized for short requests; E3/E5/E6 address longer ones. Within timing work, T1/T2/T3 dominate. Generation is a separate dependency chain, not the next item in an encoder clock-closure queue. A study can select a track without implementing all rows.

## 2. Baseline and benchmark contract

### E1: minimum measurement design

Retain the exact existing 350-case suite and model as a regression set, then add a deterministic length grid `1,2,3,4,5,12,16,17,31,32,33,64,127,128` with fixed IDs. The grid exposes pipeline fill, weight-load transition, partial query groups and maximum window. Add H1024 synthetic cases for capacity compatibility; report them separately from trained L12 quality.

For a future measurement campaign, predeclare warmups, repetition count and run order; a reasonable initial design is at least five independent runs with randomized profile order and per-length repetitions, adjusted if the observed variance demands it. Keep raw per-request records. Report median, mean, p95, p99 where sample size supports it, maximum, and uncertainty for matched differences. For rare-tail claims use enough independent observations rather than presenting p99 from a tiny sample.

Record actual PL/PS/DDR clocks, voltage/thermal/cooling state, OS/kernel, CPU affinity/governor, background load and model/capability/source hashes. Include idle and controlled shared-DDR contention as separate operating profiles. Core elapsed time must include the same work in every candidate. Export tokenizer, request write, fabric encoder, result DMA/copy, CPU heads, polling/scheduling and end-to-end application times separately. Model loading is a separate cold-start result.

Power integration must identify physical measurement point and sampling rate. Integrate whole-board energy per matched request as well as available rails; publish idle and active power separately, with and without idle subtraction clearly labeled. Do not extrapolate from Vivado power estimates or TDP. Report exactness and task-quality results next to energy/latency.

### E2: measure service before redesign

The counter evidence supports an input-path limit, but cannot distinguish every loader/DDR/control cause. A separately authorized campaign should measure accepted AR bursts and lengths, accepted R beats, AR stalls, outstanding depth, bank-full/empty occupancy, request queue occupancy, RREADY gating reasons and per-opcode bytes. Existing counters cover only a subset.

Test read-only contiguous payload service in a dedicated diagnostic context, then realistic layer streams, then full requests. Keep identical memory-region/cache treatment and record CPU contention. Separate interface clock, DDR service and consumer throttling. Any future multi-port implementation must preserve ordered logical delivery or add explicit reorder/striping rules, tails, 4 KiB handling, error aggregation and tests for independent port backpressure. Compare total transferred bytes and host costs, not only interface toggles.

Stop a bandwidth redesign if short-request useful payload improves without reducing full request latency, or if long-request energy/timing regressions exceed the declared objective. A wider bus alone is not an acceptance metric.

## 3. Exactness and timing experiments

### T1–T4: a controlled physical sequence

Start a future candidate from a new snapshot of the qualified design and change one path class. Preserve original source/package hashes. Explore capture/query locality and opcode selects independently before combining; then compare H384-specialized and H1024-capacity profiles at the same clock. Maintain a ledger of actual before/after source, mapped primitive registers, top setup/hold paths, CLB occupancy and memory mapping.

Validation order: numerical/unit and full instruction/request proofs; inference/register/primitive gates; synthesis and resource admission; placement review; only then a candidate-specific route under the existing process. The historical ≥0.5 ns placed setup admission remains unchanged; it is a gate, not a routed guarantee. Never weaken timing constraints or use false/multicycle paths to conceal functional single-cycle transfers. Record any new clock-domain assumptions explicitly.

After legal route require positive setup **and** hold, complete routing/no errors, no unconstrained internal endpoints, exact source/XSA/bit/package binding, then separately authorized hardware qualification with the preserved recovery path. A 300 MHz result needs a real 300 MHz route and live-clock verification. OOC improvement, synthesis Fmax, successful placement, a requested clock or a published design are insufficient.

Candidate benefit is full application latency or energy at fixed quality/capacity, plus useful operation rate and physical cost. If a faster clock adds more cycles, report both; if an H384 profile loses H1024 capacity, present that as a separate operating point. No candidate should replace the qualified baseline merely because a single path improved.

### E5/Q1: preserve or version numerical semantics

Use boundary tests for signed requantization ties, S=0, multiplier/shift limits, saturating residual sums, constant LayerNorm rows, maximum centered values, exponent-index254/255, probability255, all partial groups and pipeline drain. Reordering quantization/clamps or replacing two-pass variance with sum-of-squares-minus-mean changes finite-precision behavior and requires proof or a new numerical version.

For new precision/calibration models, preserve the original model and frozen references. Measure exact ImageMachine parity for the new format and separate float→quantized task quality. Use complete test splits and task-specific metrics: intent accuracy, slot F1, pair accuracy, OOS rejection/coverage, few-shot repeat variation. Do not accept only class-label parity or small 350-case accuracy as quantization quality proof.

## 4. Generative inference gates

1. **G1 contract:** pin model/revision/tokenizer and precision; implement complete embeddings, norm type, RoPE convention, attention/GQA, causal mask, gated or ordinary FFN, final norm, LM head and sampling. Existing `decoder_reference.py` explicitly lacks complete model pieces. Define intermediate widths/scales, positional limits, cache layout and reset/append semantics. Decide CPU/fabric boundaries before optimizing a kernel.
2. **Memory feasibility:** compute actual bytes after padding, quantization metadata and host copies. Include KV at maximum context, logits/embedding/head storage, temporaries and OS/runtime. Dense 0.6B W4 weights alone exceed the preserved 256 MiB region. Define a separate allocation/relative-address executor proposal; do not feed SYS3 bundles to SYS2 or assume the 40-bit master solves 32-bit ABI limits.
3. **G2 baseline:** use the pinned Qwen CPU preparation as a candidate baseline only after checking the saved provenance. Laptop startup/first-word results are not KR260 results. Compare Q8 and the explicitly requantized Q4 model at the same prompt/output policy. Validate negation, context and task usefulness; low TTFT with wrong answers is not success.
4. **G3 correctness:** prove full-sequence causal reference equals prefill plus successive cache-appends for an exact numerical path. Cover context1, boundary heads/groups, maximum context, cache reset between requests, model switch, overflow/rejected capacity and output termination. Test cache coherency and write/read ordering before full layers.
5. **Complete-system performance:** report cold startup; tokenizer; prefill kernel and host; TTFT from submitted prompt to first generated token; time to first visible/non-whitespace answer separately if useful; decode latency by context; generated tokens/s excluding prompt tokens; EOS/truncation; LM-head and synchronization time; energy/prompt and energy/generated token. Fix prompt lengths64/128 plus a context sweep and fixed generation counts. Distinguish first token produced by prefill from subsequent decode iterations.
6. **Choose G3 versus G4 using evidence:** standard-model W4 with mixed precision and native ternary LUT inference have different quality, memory and resource tradeoffs. Do not evaluate them by token rate alone. A hybrid path should fuse enough adjacent operations to amortize CPU/fabric transfer; a kernel-level speedup must pass the end-to-end Amdahl check.

## 5. Publication deliverables and stopping conditions

The strongest immediate research asset is the exactness-preserving encoder co-design study. Produce an ablation table with one row per capacity/storage/control/pipeline change: source hash, routed resources/clock, cycles by length, exactness, energy and noise. Include failed/rejected candidates with their actual admission reason, without treating them as deployable results. Use model-size and sequence-length scaling to test the analytical crossover rather than quoting one favorable input.

Do not claim new architecture contributions for standard buffering, integer BERT, on-chip intermediates, higher clock alone or hardware qualification alone. Claim a measured methodology or mechanism only after the relevant ablation. A generative paper additionally needs a complete model, reproducible model quality and matched baselines. If memory feasibility, quality or end-to-end benefit fails, retain that negative result and stop that branch before committing to a full hardware redesign.

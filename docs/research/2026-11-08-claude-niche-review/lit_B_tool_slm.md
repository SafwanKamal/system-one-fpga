## 1. What is saturated

- **Synthetic function-calling data plus SFT of 1–8B models** (APIGen, APIGen-MT/xLAM-2, ToolACE, Hammer, ToolLLM, Gorilla). Every lab has a data pipeline that pushes 7–8B models to "GPT-4-level on BFCL". Another dataset or fine-tune is not a contribution.
- **Single-turn BFCL AST accuracy.** The BFCL authors themselves say single-turn is solved for SOTA models, and 1B models (xLAM-1b, Hammer-1.5B) score well on simple and multiple categories. Reporting single-turn BFCL alone is not novel.
- **GPU-side constrained-decoding engines** (Outlines, XGrammar, SynCode, llama.cpp GBNF, Guidance). Speed and coverage are well studied (JSONSchemaBench), and syntax validity is effectively solved by masking.
- **Laptop/phone/Jetson SLM agents** (TinyAgent, Octopus, FunctionGemma demos, "Less is More", TinyLLM). "A small model calls tools locally" has been demonstrated many times on CPU, GPU and NPU.
- **Position and survey papers** arguing SLMs suit agents (Belcak et al. and many surveys).

## 2. Gaps and open niches tied to our assets

1. **Deterministic, replayable tool calls on edge hardware (strongest niche).** None of B01–B15 or B36 claims bit-exact reproducibility. B39 shows GPUs need special kernels and give up throughput to get it, and our own llama-server check broke under caching. On a full-fabric decoder, τ-bench's pass^k (B20) collapses to pass^1 for a fixed input, so reliability becomes a property of input distributions, not sampling or batching noise. Possible paper: "deterministic edge tool agents: auditable, replayable function calls with bit-exact prefix reuse".
2. **Exact prefix reuse with proven output identity.** Prefix/KV caching is common, but no small-agent paper shows that caching leaves outputs **bit-identical** (our 328/328). That fits safety- or audit-critical settings such as industrial maintenance logs.
3. **Typed JSON state as agent memory, verified.** MemGPT (B30) and ACON (B31) compress context in free text. ACON reports 26–54% peak-token savings, and ours is 89.5% with a schema-validated state. "Schema-typed memory for a 0.6B agent under a 2K context" is not studied. Evaluate on BFCL V4 memory or an ACON-style long-horizon task.
4. **Grammar masks in hardware.** XGrammar's precomputed context-independent masks and SynCode's DFA mask store are lookup tables. No work puts grammar-constrained decoding *inside an FPGA LM head*, which would make "invalid JSON is impossible" a hardware guarantee next to the integrity seals. B24/B25 caveats apply: report likelihood distortion as well as validity.
5. **Decision heads instead of generation for small models.** Octopus functional tokens (B02), B27 (structure helps classification, hurts reasoning) and B37/B38 (probes on hidden states) all suggest a 0.6B model should *choose* among typed candidates rather than *write* plans. Our candidate-scoring heads with calibrated abstention match this. A comparison of "generation vs head-over-hidden-state on the same frozen 0.6B, on the same fabric" with calibrated coverage-accuracy curves is not in the literature.
6. **Nested and conditional maintenance planning.** NESTFUL (B16) shows nesting is hard even for GPT-4o (25% full-sequence match). Our crossed-conditional set (Qwen3-1.7B 0/64; rules 120/120) is a domain instance. A neuro-symbolic split (the LM extracts typed slots, a deterministic planner composes them, LLMCompiler/ReWOO style) is under-studied below 1B and in industrial maintenance.
7. **Energy per verified tool call.** "Less is More" (B36) reports power on a Jetson, and B14 reports CPU latency and memory but no energy. The first J/verified-call number on a full-fabric LLM would be new, but we have measured nothing yet. This is the biggest gap in our evidence.

## 3. What small models can and cannot do reliably (per the literature)

**Can (with fine-tuning, narrow schema, few tools):**
- Single-turn calls on a fixed, small API set: MobileLLM-350M matches LLaMA-2-7B exact match on its API task (B11). FunctionGemma-270M goes 58% → 85% on Mobile Actions after fine-tuning (B04). Octopus-2B is accurate on about 20 Android APIs with functional tokens (B02). xLAM-1B/APIGen-1.3B are competitive on BFCL single-turn (B06/B07). In our own data, software Qwen3-1.7B scores 172/200 on the BFCL subset.
- Choosing among few tools improves sharply when the tool list is pruned: up to 70% lower latency and 40% lower power (B36). TinyAgent's Tool-RAG has a similar effect (B01).
- Classification-style decisions under strict formats (B27), and probes over hidden states (B37/B38).
- Syntax validity can be 100% *with* constrained decoding (B23: JSON syntax errors eliminated), independent of model size.

**Cannot (reliably):**
- **Multi-turn below 1B:** TinyLlama-1.1B reaches 0.00% multi-turn BFCL and 19.7% overall. The best 1–3B gets 55.6% multi-turn and 65.7% overall even after SFT+DPO (B13).
- **Raw JSON format adherence without constraints:** the best sub-2B model had a 79% recovered-call rate but only about 5% strict whole-response JSON validity. 1.4B models score 0–7%, and size does not predict reliability (B14).
- **Nested and sequential calls:** even the best model reaches 25% full-sequence match on NESTFUL (B16). Small models are worse (in our data, 1.7B gets 0/64 on conditional plans).
- **Consistency:** GPT-4o pass^8 < 25% on τ-retail (B20). Small models have no published pass^k results, which is a gap our determinism can fill.
- **Robustness to schema renaming:** small function-callers overfit to names (B05).
- **Reasoning under strict format:** JSON-mode reasoning accuracy drops (B27), and grammar masking distorts the distribution (B24).

**Bottom line from the literature:** a sub-1B model is reliable as a **constrained selector or slot-filler over a small typed schema, with external validation**. It is not reliable as an autonomous multi-step planner. That matches our "bounded reliability" framing, and B14 reaches the same conclusion on CPU.

## 1. What is saturated

- **Generic LLM routers and cascades for API cost** (FrugalGPT, RouteLLM, Hybrid LLM, cascade routing, token-level deferral, speculative cascades). Most measure cost against quality on MMLU, GSM8K or MT-Bench with GPU or cloud models. A new router or a new deferral feature on public chat benchmarks would not be a contribution.
- **Conformal prediction wrappers for LLM QA and generation** (conformal LM, conformal factuality, KnowNo-style MCQA sets, LLM-judge selective evaluation). The theory is mature, and 2026 already has conformal cascades with cascade-level guarantees (D38).
- **Agent guardrail DSLs and policy shields** (AgentSpec, ShieldAgent, Progent, GuardAgent, RoboGuard, SELP). Software-only runtime enforcement on AgentDojo-style benchmarks is crowded.
- **Cloud-LLM industrial agent benchmarks run by IBM** (FailureSensorIQ, AssetOpsBench, PHMForge, Condition Insight). IBM owns this space. Its results consistently show that structure, tools and verification beat bigger backbones, so restating that alone is not new.
- **Maintenance-log classification with frontier LLMs** (wind turbine logs, data cleaning, synthetic work orders).
- **LLM-to-PLC code generation with verifier loops** (LLM4PLC, Agents4PLC and follow-ups).

## 2. Gaps and open niches tied to our assets

1. **Deterministic tier-1 makes conformal guarantees auditable.** Every conformal and cascade guarantee (D20–D24, D37–D39) assumes the score function is fixed across calibration and deployment. On GPU or CPU stacks, logits shift with batch shape, caching and kernels; we saw this directly in our llama-server prefix-cache mismatch. A bit-exact FPGA System-1 makes the calibration set replayable and the guarantee checkable by a third party. Nobody in the literature found states this. *Niche: "replayable conformal escalation", where the guarantee comes with an evidence seal.*
2. **Calibrated abstention over typed, field-level structured outputs.** Function-calling UQ appeared only in 2026 (D24) and reports AUROC, not coverage or risk guarantees. KnowNo-style sets over a typed action vocabulary, and Mohri-style field back-off on typed plans, are open for tool calls and maintenance plans. Our assets fit: the v1 integer-folded temperature calibration, decision heads over frozen states, and typed output schemas.
3. **LLM-Modulo with a sound rules engine as verifier in OT, on device.** D05 and D12 confirm industry wants deterministic evidence plus rule verification, but both run in the cloud or on a workstation. Our result (rules engine 120/120, small LLMs poor on full plans) should be reframed: the LLM's job is to normalise and extract typed slots (MaintNorm/MaintIE-style) and to propose, while the rules engine plans and verifies. The claim to measure is coverage-at-risk, not plan accuracy. No paper reports an on-device, air-gapped LLM-Modulo loop with abstention for OT.
4. **Edge-first escalation in OT with network-failure semantics.** Hybrid LLM, RouteLLM and speculative cascades assume the cloud tier is always reachable. In OT the cloud can be unavailable or forbidden by policy (IEC 62443 zones). A guaranteed cascade in which the escalation target is a human or the rules engine rather than a cloud LLM, with a deterministic fallback, is unaddressed.
5. **Hardware-enforced action gating.** The guardrail DSLs (AgentSpec, Progent) run in the same software trust domain as the agent. Our R5 real-time core ownership, typed output path and sealed weights let us put an AgentSpec-like rule check outside the LLM's trust domain, which is new for LLM agents in OT.
6. **Constrained decoding against typed schemas or LTL in fabric** (SELP-style). A deterministic logit mask in the HLS decoder that enforces a JSON or ISO 14224 grammar costs almost nothing per token and has not been shown on FPGA LLMs.
7. **Small-model honesty.** Few results exist on calibration of sub-1B LMs for structured industrial decisions. ASPIRE (D18) suggests small adapted models can be good selective predictors, which supports our decision-head direction.

## 3. Public benchmarks to adopt instead of (or alongside) our template-derived set

| Benchmark | Why it fits | How we would use it |
|---|---|---|
| **AssetOpsBench** (D02; HF ibm-research/AssetOpsBench) | Real, human-authored industrial queries; work-order and FMSR agents; public leaderboard | Run the work-order and FMSR subset with an on-device System-1 plus escalation; report coverage, risk and latency |
| **PHMForge** (D03) | Deterministic evaluators, MCP tools, open leaderboard | The tool-calling path with typed outputs and verified execution; measure abstain-when-wrong |
| **FailureSensorIQ** (D01; github IBM/FailureSensorIQ) | 8,296 MCQA items with objective answers; suits logit-based conformal sets on 0.6B | Selective accuracy and conformal set-size curves; KnowNo-style singleton-or-escalate |
| **MaintIE** (D07) and **MaintNorm** (D06) (github nlp-tlp) | Real work-order text with gold typed entities, relations and normalisations | Extraction and normalisation as System-1 tasks feeding the rules engine; replaces template text with real operator language |
| **Wind turbine maintenance-log labelling** (D08; github mvmalyi) | Real logs; known ambiguity split (component vs action) | Test whether calibrated abstention concentrates on the interpretive fields |
| **PHM-Bench** (D04) | Fault diagnosis, RUL and maintenance-decision taxonomy | Secondary, for coverage of decision-type questions |
| **BFCL** incl. the Irrelevance split, with the D24 protocol | Already in use; D24 provides the UQ protocol (AST correctness, AUROC) | Report AUROC plus conformal coverage directly comparable to D24 |
| **ClarifyBench** (ACL Findings 2026) | Multi-turn tool-calling disambiguation; abstain-or-ask | Interactive proposal path (currently 41/120) |

Recommendation: keep the template set only as a controlled stress test (crossed-conditional), and make headline claims on AssetOpsBench or PHMForge subsets plus MaintIE/MaintNorm real text, with risk–coverage curves and a replayable conformal guarantee.

# Broad edge-ML and FPGA architecture search

November 8, 2026. This search deliberately starts from continuous sensing, resource allocation and adaptation. The proposed systems can use a fresh implementation and different models. The literature was screened through primary abstracts and selected full text. The candidates below are research hypotheses. The search does not establish an exclusive first claim for any of them.

My preferred cheap experiment is **joint acquisition and delayed-label adaptation**, described in direction 3. It tests an interaction between temporal acquisition availability and learning evidence. A follow-up novelty check found that active acquisition and drift-aware online learning are already combined, so this candidate's opening is narrower than its title suggests. The best direct FPGA architecture candidate is **freshness-aware sharing of continuous neural sensor features**, described in direction 1. Its nearest existing systems are close enough that the first experiment must demonstrate a benefit beyond ordinary shared preprocessing. Generic scheduling, static sensor-to-text translation and an online-trained linear head are mature topics.

## 1. Share computation across changing continuous sensor queries

**Problem.** A sensory edge hub serves several tasks over the same incoming channels. Their windows, output cadence and desired temporal resolution differ. A person may add a retrospective query while continuous detection continues. Independently running a network per task repeats window preparation and feature extraction. Precomputing every possible representation wastes work when queries change.

**Concrete candidate.** Build a small bank of incremental time-domain and spectral features plus one shared sensor encoder. An ARM planner turns query specifications into feature/window dependencies. A PL pipeline updates only the selected feature groups at selected cadences, shares them among active task heads, and stores a hierarchy of summaries for longer retrospective windows. The scheduler chooses between refreshing a feature, answering from its current representation or computing a requested window from retained samples. The machine-learning question is how task error depends on representation age and resolution. The architecture question is whether a shared incremental representation beats a generic CPU/NPU pipeline at the actual sensor and query rates.

An example workload could combine vibration-event detection, an operating-state classifier and a query for the duration of a particular activity over the past ten minutes. Natural language can be an optional interface. Evaluation should use frozen machine-readable queries so language parsing does not dominate the experiment.

**Strongest counterargument.** This could be SensiX++ with FPGA preprocessing, or an ordinary materialized-view optimizer with neural operators. A direct row of moments and FFT features may run cheaply enough on the A53 that moving it to fabric has little end-to-end value. At low-rate wearable inputs, raw storage can be inexpensive and preserving all samples can dominate a complex retention policy.

**Cheap falsification.** Start with two independently collected sensor datasets, three task heads and varying query mixes. Implement a vectorized CPU shared pipeline, an eager all-feature pipeline, independent per-task pipelines and a freshness-aware scheduler. Separate raw-window cost, transformations, encoder cost, head cost and stored bytes. Include an efficient sensor-embedding baseline and static feature sharing. Freeze query mixes before evaluation. Reject this direction if sharing with a static cadence achieves the same task accuracy and response time within 10% resource cost, or if feature maintenance is under 20% of total cost at a realistic target scale. These are proposed experiment gates.

**FPGA feasibility.** Streamed reductions, FFTs, short 1D convolutions and fixed-width task heads fit the platform well and avoid loading a generative model. Throughput pressure must be demonstrated. A 64 kHz, 16-bit channel produces 128 kB/s. One hundred such channels produce 12.8 MB/s and 7.68 GB over ten minutes. That is a useful scaling arithmetic example, with recorded-channel replication counting only as a throughput stress test. It does not establish that a deployment has 100 independently useful channels. Input buffering and the real sensor/transport interfaces belong in the budget.

## 2. Schedule useful freshness across competing edge tasks

**Problem.** Frame or window deadlines are convenient scheduling units but the value of a refreshed output depends on the task and environment. A slowly changing task can tolerate stale features. A brief event may need rapid refresh. Shared feature extraction creates an additional coupling between tasks, and occasional adaptation or new query initialization consumes the same memory bandwidth.

**Concrete candidate.** A heterogeneous runtime jointly chooses the feature refresh cadence, shared execution groups and CPU/PL placement for several sensor models. Its objective is measured task utility over time under an energy or memory-traffic budget. A task gets a model of error versus feature age and event state, learned from a held-out profiling stream. The scheduler operates over groups with common feature dependencies rather than treating every model as an independent periodic job. The FPGA hosts the sustained shared feature pipeline. ARM runs placement and task-specific adaptation.

**Strongest counterargument.** A new scheduler can win against FIFO while losing to ordinary earliest-deadline scheduling, static shared trunks or a carefully profiled round robin. Optimization over an invented utility curve gives little deployment evidence. Existing work spans most individual ingredients.

**Cheap falsification.** Trace-replay several real tasks with independently chosen output cadences. Compare FIFO, earliest deadline first, fixed-priority, static shared-feature cadence, an age/error scheduler from prior work, a model-selection baseline and the proposed dependency-aware policy. Count stale-output task errors and missed transient events, along with traffic and energy proxies. Include changing task mixes and correlated bursts. If a simple static shared schedule tracks the proposed policy closely, discard the scheduler contribution. Hardware development starts only when a profile shows shared sensor preprocessing or memory contention is a substantial bottleneck.

This direction ranks behind direction 1. It is best treated as a systems extension if the shared-feature workload reveals a meaningful interaction. Generic multi-model resource scheduling has too much close prior art to lead the project on its own.

## 3. Co-design acquisition and learning when labels arrive late

**Problem.** Adaptive sensing saves acquisition and compute by taking fewer samples when the current classifier is confident. A change in environment or sensor placement can make that classifier confidently wrong. Labels often arrive minutes or hours later. The acquisition policy then changes which examples can enter the learner, while the delayed-label learner operates on an already selected stream. Running an adaptive sampler and an online learner independently can therefore lose exactly the examples needed for adaptation.

**Concrete candidate.** A heterogeneous sensory node allocates a small budget to exploration samples independently of the current classifier. Most input follows a cheap low-resolution path. Selected windows retain richer samples or features until a label deadline. The planner jointly decides what to acquire, how much representation to keep and whether to adapt from an arriving delayed label. The PL maintains multirate features and the bounded retention path. ARM updates a small head/prototype model or chooses among previously trained sensor adapters.

The candidate combination is **temporally irreversible acquisition × delayed feedback × representation retention cost**. Each ingredient is established. The concrete research question is whether coordinating them moves the quality-versus-total-resource frontier on real sensor drift compared with strong active-feature learners. Exploration and label acquisition must have explicit costs.

Temporal irreversibility is essential to making the question substantive. A scalar tabular feature-query model can reveal an attribute of the current example whenever requested. A burst waveform or spectral window needs samples from a period that may already have passed. Turning on a channel now can require sensor warmup and enough future samples to fill a useful window. A late label may arrive after the corresponding raw window was discarded. These change the feasible action set and memory tradeoff. A worthwhile mechanism would plan around those availability dependencies. Merely delaying an existing learner's posterior update and adding a reservoir would be a weak extension.

**Strongest counterargument.** A small fixed exploration rate plus a delayed-update active-feature learner may already solve the problem. The proposed method could amount to joining familiar algorithms. A frozen encoder with a tiny CPU head may make FPGA adaptation unnecessary. The FPGA needs to earn its place through input scale, low-overhead multirate processing or measured reduction of transfer/representation cost. Presenting only a synthetic label delay would add little to the existing feature-drift and label-delay literature.

**Cheap falsification in one software campaign.**

1. Pick two public raw sensor datasets with genuine user/device/session splits. Introduce label delays by releasing original labels later in time. Report synthetic delays separately from natural acquisition shifts. Preserve an untouched chronological test stream.
2. Compare full-rate frozen inference, fixed reduced sampling, AdaSense-style adaptive sensing, adaptive sensing plus fixed random exploration, a delayed-label learner at fixed sampling, Beyer-style feature acquisition and delayed-update UFODT with a memory buffer.
3. Add a joint retention/acquisition policy only after those controls work. Compare raw-window, quantized-feature, prototype and reservoir retention at the same byte budget.
4. Use held-out device/user changes and transient event transitions. Include matched zero-warmup/tabular and real-window-availability arms to isolate whether temporal irreversibility changes the policy result. Report event recall, delay to adaptation, old-domain forgetting, bytes acquired, retained bytes, feature-compute work and label cost. Count every exploration sample.
5. Kill the new-policy claim if delayed-update UFODT with a fixed exploration budget and ordinary retention reaches the same quality frontier within 10% resource cost, or if removing physical availability constraints leaves the claimed advantage unchanged. Kill the FPGA claim if an ARM/MCU implementation meets the selected input rate and latency with comparable total energy.

On replay, skipped input bytes and reduced operations are measurable. Physical sensor-energy saving requires a real acquisition path and sensor duty-cycle measurement. Input throttling after an ADC or sensor has already sampled supplies no acquisition-energy evidence. The KR260 has no built-in fast analog acquisition path, so an eventual board experiment needs a suitable sensor/ADC or a networked sensor whose behavior is actually controlled.

## Ranking and next decision

| Candidate | New capability sought | Main missing evidence | Cheapest first discriminator |
|---|---|---|---|
| Joint acquisition and delayed adaptation | Stay adaptable under reduced sensing and delayed feedback within a bounded retention budget | Benefit beyond fixed exploration plus existing replay, followed by hardware necessity | Chronological sensor replay with equal acquisition/retention budgets |
| Shared fresh features for changing queries | Serve several sensor tasks and retrospective windows without computing every representation continually | Benefit beyond SensiX++ and incremental stream processing | Vectorized shared-pipeline profile under frozen query mixes |
| Freshness-aware heterogeneous scheduling | Spend refresh/adaptation work where it changes delivered task accuracy most | Benefit beyond established scheduling and model-selection policies | Trace-driven comparison with strong static and age-based schedules |

The first two can share a small sensor encoder and multirate feature pipeline later, but they should begin as separate scientific questions. Combining all three before an observable effect appears would obscure which mechanism matters. Neither candidate requires another LLM accelerator.

The broad search found several close predecessors that weaken simple proposal titles. It did not produce an established unoccupied niche. The recommended contribution is conditional on a cheap, controlled interaction experiment that can fail, then a measured system where the FPGA's streaming architecture changes that result.

## Discussion after comparing the independent application search

My broader scientific ranking is manual-conditioned diagnostic transfer first, future-question evidence memory second and delayed-feedback acquisition third. This ranks the value of a decisive experiment and the clarity of the bottleneck. It does not certify novelty, and all three have direct prior work. A generic optimization wildcard has no defined task or strong baseline yet and ranks below them until specified.

The manual direction should survive the strongest objection before a project pivot. The input component library and topology graph may already contain everything a deterministic assembler needs. BMD can also receive the same manual and component knowledge. A result against an underinformed BMD baseline would therefore overstate the language method's value.

One experimental outcome would justify pursuing the pivot. On independently authored manuals for completely held-out equipment and topology families, the generated model should achieve intervention prediction and costed diagnostic performance close to an expert's model, while using materially fewer expert correction minutes than both a deterministic component assembler and BMD with the same information and numerical planner. Count rejected models, calibration observations and all human corrections. The required improvement in effort and tolerated diagnostic loss should be frozen after a feasibility pilot. A component-name paraphrase test or an additional random tank parameter supplies insufficient transfer difficulty.

A further primary check found direct precedent that narrows this thesis. Merkelbach et al., DX 2024, use a five-step multimodal prompt workflow to construct physical models from P&IDs and natural language, then generate residuals and fault-signature analysis with the Fault Diagnosis Toolbox. They evaluate one-, three- and four-tank systems and explicitly motivate lower model-authoring cost across architectural/product changes. They also describe weak generalization outside familiar tank systems. This makes their workflow a required baseline alongside BMD. An active-test, cross-family transfer result would have to advance that documented limitation. [Primary paper](https://drops.dagstuhl.de/entities/document/10.4230/OASIcs.DX.2024.31), [artifact](https://github.com/silkeme/DX24_Model_Creation_LLMs).

The future-question memory idea is attractive because evidence discarded before a question arrives cannot be recovered. Its opponent is the simple combination of interval-aware event records, multiresolution statistics, a raw-data reservoir and ordinary retrieval. The learned method needs to beat that combination on independently chosen unseen temporal questions at the same total byte budget. General bounded-memory streaming QA already has extensive precedent, as the application review documents.

The acquisition idea has a narrower residual after the UFODT check. Its best case depends on physical window availability, warmup and a finite retention horizon affecting the feasible policy. If adding those constraints merely changes a cost coefficient in a conventional active-feature learner, the result may be useful engineering but provides little algorithmic novelty. That is why its first experiment explicitly compares delayed UFODT with ordinary retention.

None of these scientific directions automatically requires programmable logic. An FPGA architecture paper needs a measured workload where continuous input processing, overlapping temporal feature updates or scarce data movement supplies a benefit beyond a well-tuned CPU/MCU/NPU implementation. Establishing that boundary is preferable to assuming a new application must preserve the original board as its main compute engine.

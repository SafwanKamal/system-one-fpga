# v9i routed fit (2026-11-22)

v9i = full dual weight port (D3: `build/v2/dual-port-study/src-d3`) + P=2 attention, generated by
`make_v9i.py` and built by `build_v9i.py all` using v9h's exact flow and constraints. Vivado 2025.2,
xck26-sfvc784-2LV-c. Outputs are in `build/v2/v9i/impl/` (not committed).

**It fits and meets timing.** Implementation took 57 minutes and finished with 0 errors and
0 critical warnings. The flow's own timing gate passed, and it wrote `system_wrapper.bit` and
`qwen_decoder.xsa`.

|---|---:|---:|---:|
| CLB LUT | 101,844 (86.96%) | **92,728 (79.17%)** | −9,116 |
| CLB (slices) | 14,584 (99.62%) | 14,570 (99.52%) | −14 |
| CLB registers | 102,629 | 101,740 | −889 |

| URAM | 40 | 40 | 0 |
| WNS / WHS (ns) | 0.357 / 0.010 | 0.343 / 0.003 | |
| Worst bus skew slack (ns) | | 2.787 (all met) | |

The CLB slice count stays at 99.5%. Vivado spreads logic across almost every slice regardless, so
LUT count is the meaningful headroom number: 9.1k LUT were freed, even though v9i adds the second
weight port.

port's cost: the reclaim study predicted about 99k for the decoder; it routed at 87.8k.

## Not covered here

- Bit-exactness against v9h: not established in this commit. Codex's decode-mode C-sim job (0fd992dbec32) blocked without publishing, and decode mode (one token per pass) would not exercise P=2 anyway. A prefill-mode full-decoder C-sim is the follow-up.
- Board timing and throughput: the modelled 1.31x on tool queries is unmeasured until a board pilot,
  which needs the user's approval.

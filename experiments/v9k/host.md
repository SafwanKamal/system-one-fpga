# B=16 host and firmware implications

The RC1.3 service already groups the uncached prompt suffix using `e.prefill_batch_size`. Each group carries its absolute start position, and only the final group requests logits. RC1.4 uses the same pattern for v9i. The v9h experiment pilot uses the same engine property and grouping loop from position zero for a cold prompt. [RC1.3 service, lines 90–97](../../firmware/rc1_3/spec_service_rc13.py#L90-L97), [RC1.4 service, lines 80–87](../../firmware/rc1_4/spec_service_rc14.py#L80-L87), [v9h experiment, lines 102–109](../dual_port/v9h_pilot.py#L102-L109)

1. Publish `model_profile.prefill_batch = 16` in the v9k app's `build.json`. Update the candidate packager's batch check and make the runtime's batch guard accept 16 for the verified v9k image. The current guard rejects any value other than 8 before assigning `e.prefill_batch_size`. Wire the new image and overlay compatible, package pins and service identity through the versioned install and runtime loader. The existing v9h register-map override remains valid, including `model_b` at `0x70` and the shell's scratch mapping at `0x7c`. [Candidate runtime, lines 54–96](../../src/sysone/v2/qwen_fpga_runtime_candidate.py#L54-L96), [Packager, lines 49–58](../../scripts/v2/package_hardware_candidate.py#L49-L58), [RC1.3 loader, lines 20–36](../../firmware/rc1_3/spec_service_rc13.py#L20-L36), [RC1.3 installer, lines 125–141](../../firmware/rc1_3/install_rc13.py#L125-L141)
2. Keep the existing `prefill_batch` command sequence. Command 7 gets 16 32-bit embedding offsets at `0x2100` (64 bytes, ending before `0x2140`). Command 8 gets `rows=count` for each layer with the same absolute position. Command 9 selects `layer=count-1` for the final group's logits. Keep the short tail and the existing `position + count <= context` validation. The embedding list fits between the layer descriptor at `0x2000` and output at `0x3000`, and the runtime already handles a full aligned 64-byte scratch write. MMIO writes use 32-bit values. [Scratch offsets, lines 21–31](../../src/sysone/v2/qwen_fpga_runtime_candidate.py#L21-L31), [MMIO and scratch writes, lines 135–154](../../src/sysone/v2/qwen_fpga_runtime_candidate.py#L135-L154), [Commands, lines 178–193](../../src/sysone/v2/qwen_fpga_runtime_candidate.py#L178-L193), [Batch and final head, lines 204–227](../../src/sysone/v2/qwen_fpga_runtime_candidate.py#L204-L227)
3. Preserve cache identity checks and final-token replay when the prefix matches. Qualify the new image with cold and reused prefixes, tails of 1 and 15, a full group of 16, a group crossing a 256-position attention tile, and the context boundary. Use physical group and weight-pass counters alongside prompt, logits and output parity. Speculative draft length is a separate tuning parameter. If verification also expands to 16 slots, its existing commands 11/12 pass the count in `rows`/`layer` and read 16 result slots at 32-byte stride (512 bytes starting at `0x3000`, below RoPE at `0x10000`). ## Modelled gain per tool query

The RC1.3 reference is **0.56 s/query** for the user-specific prompt suffix. I took the 21 tool cases' prompt lengths from the local `build/v2/v9g-board/pilot.json` used by the attention-reclaim model and deducted its cached 32-token template. The uncached lengths were 20–28 tokens. That gives 70 B=8 groups versus 42 B=16 groups across the sample, a **40% reduction in decoder-layer weight passes**. [RC1.3 handoff, lines 86–91](../../docs/HANDOFF.md#L86-L91), [Replay data, lines 46–63](../draft_research/replay.py#L46-L63), [Attention-reclaim model, lines 20–37 and 62–69](../attn_reclaim/model_p2.py#L20-L69)

I used the same seven-coefficient v9h board fit as the attention-reclaim model. For each group of `k` tokens starting at absolute position `p`, it charges `port_cost + c_tok*k + c_pos*p + c_grp*p*ceil(k/P)`. It uses the separate fitted single-step cost for `k=1`. RC1.3 uses dual ports for groups of up to four and P=4. The full dual-port v9i and v9k arms use the lower dual-port group cost at every size and P=2. The model extrapolates the per-token and attention terms through 16 tokens and assumes the same operating clock and weight service. I scaled all three raw means by `0.56 / 0.685` to anchor the comparison to the observed RC1.3 suffix timing. [Fit construction, lines 44–69](../rc13/fit_v9h.py#L44-L69), [Pass cost, lines 25–39](../attn_reclaim/model_p2.py#L25-L39)

B=16 contributes **about 0.093 s/query** of incremental prefill savings versus v9i (**24%, 1.31× prefill**). The combined dual-port and wider-batch projection is **about 0.262 s/query** versus RC1.3 (**47%, 1.88× prefill**). The fit omits an explicit final-head or host-overhead term and extrapolates beyond the measured batch range. These figures describe prefill only and assume v9k can be implemented at the assumed clock.
